SmartResolve AI - Part 9: RAG with PostgreSQL and pgvector

12.1 Objective

Part 9 adds Retrieval-Augmented Generation (RAG) to SmartResolve. RAG allows the AI assistant to search verified knowledge articles before generating an answer.

Employee question
    -> Question embedding
    -> pgvector similarity search
    -> Relevant verified articles
    -> Retrieved context added to the AI prompt
    -> Llama 3.2 generates the answer

12.2 Why RAG Is Required

A general-purpose LLM does not automatically know SmartResolve's internal support knowledge. RAG retrieves relevant internal solutions from PostgreSQL and supplies them to the model as context.

This improves answer relevance and allows verified troubleshooting knowledge to be reused.

12.3 Embeddings

An embedding is a numerical representation of text. The embedding model converts knowledge article content and employee questions into vectors. PostgreSQL compares these vectors to find semantically similar information.

For example, the questions "Laptop Wi-Fi is not working" and "My computer keeps disconnecting from the wireless network" can be recognized as related even though their wording differs.

12.4 AI Models

ModelResponsibility
llama3.2Understands questions and generates final chat and RAG responses.
mxbai-embed-largeCreates vectors for articles and questions for similarity search.
ollama pull llama3.2
ollama pull mxbai-embed-large
ollama list

The two models have separate responsibilities. Installing the embedding model does not replace or disable the chat model.

12.5 PostgreSQL and pgvector

The application uses the pgvector/pgvector:pg17 PostgreSQL image. pgvector allows PostgreSQL to store embeddings and perform similarity searches.

SettingValue
Vector dimensions1024
Distance typeCosine distance
Index typeHNSW
Vector tablesmartresolve_knowledge_vectors

These settings are configured in application.properties. The vector dimensions must match the embedding model output.

12.6 Knowledge Article Storage

Verified articles are stored in the knowledge_articles table.

ColumnPurpose
idKnowledge article identifier
titleArticle title
contentVerified solution content
source_ticket_idOptional source ticket
verifiedWhether the article is verified
activeWhether the article is available for retrieval
verified_byUser who verified the article

Only articles with verified = true and active = true are retrieved.

12.7 Vector Storage

The generated embeddings are stored in smartresolve_knowledge_vectors. Spring AI stores the document text, embedding vector, and metadata.

Metadata includes:

articleId
title
verified
active
sourceTicketId

When an article is created, the backend saves the relational article and then indexes a document in the vector store.

12.8 Create a Knowledge Article

POST http://localhost:8080/api/knowledge/articles
Authorization: Bearer <ADMIN_OR_SUPPORT_ENGINEER_JWT>
Content-Type: application/json
{
  "title": "Frequent Wi-Fi disconnections on Windows laptop",
  "content": "Open Device Manager and update the Wi-Fi adapter driver. Restart the WLAN AutoConfig service. Forget the wireless network and connect again. If the issue continues, restart the router and check for interference.",
  "sourceTicketId": null
}

The endpoint saves the article, creates its embedding using mxbai-embed-large, and indexes it in pgvector.

{
  "id": "KNOWLEDGE_ARTICLE_ID",
  "title": "Frequent Wi-Fi disconnections on Windows laptop",
  "sourceTicketId": null,
  "verified": true,
  "verifiedBy": "Neha",
  "createdAt": "2026-11-15T17:10:00"
}

12.9 Retrieve Verified Articles

GET http://localhost:8080/api/knowledge/articles
Authorization: Bearer <ADMIN_OR_SUPPORT_ENGINEER_JWT>

This endpoint returns active and verified knowledge articles.

12.10 RAG Chat API

POST http://localhost:8080/api/ai/rag/chat
Authorization: Bearer <EMPLOYEE_JWT>
Content-Type: application/json
{
  "conversationId": null,
  "message": "My Windows laptop disconnects from Wi-Fi frequently. What should I do?"
}

A null conversation ID creates a new RAG conversation.

{
  "conversationId": "RAG_CONVERSATION_ID",
  "answer": "According to the verified knowledge article, you should update the Wi-Fi adapter driver, restart the WLAN AutoConfig service, and reconnect to the wireless network.",
  "sources": [
    {
      "articleId": "KNOWLEDGE_ARTICLE_ID",
      "title": "Frequent Wi-Fi disconnections on Windows laptop",
      "sourceTicketId": null
    }
  ],
  "timestamp": "2026-11-15T17:15:00"
}

The sources list proves that a knowledge article was retrieved.

12.11 RAG Retrieval Process

The service searches for up to five relevant documents and applies a similarity threshold of 0.60:

topK = 5
similarityThreshold = 0.60
filter = verified == true && active == true

Only relevant, verified, and active documents are supplied to the LLM.

12.12 How Retrieved Knowledge Reaches the LLM

The RAG service retrieves matching documents and builds a knowledge context containing the article title, IDs, and verified solution. That context is appended to the system prompt.

System instructions
+ Retrieved verified knowledge
+ Previous conversation messages
+ Current employee question
    -> Llama 3.2
    -> Final answer

The embedding model does not generate the final answer. It only creates vectors for retrieval. Llama 3.2 generates the final response.

12.13 RAG Conversation Memory

RAG chat uses the existing JDBC conversation memory.

TablePurpose
chat_conversationsStores conversation ownership, title, and timestamps.
SPRING_AI_CHAT_MEMORYStores user, assistant, system, and tool messages.

Use the same conversation ID for follow-up messages:

{
  "conversationId": "RAG_CONVERSATION_ID",
  "message": "What solution did you mention earlier?"
}
Do not send null for a follow-up message. A null conversation ID creates a new conversation.

12.14 Complete RAG Processing Flow

  1. An administrator or support engineer creates a verified knowledge article.
  2. The article is saved in knowledge_articles.
  3. The article is converted into an embedding.
  4. The embedding is stored in smartresolve_knowledge_vectors.
  5. An employee sends a question to /api/ai/rag/chat.
  6. The question is converted into an embedding.
  7. pgvector searches for similar articles.
  8. Verified and active articles are selected.
  9. The article content is added to the AI prompt.
  10. Previous messages are loaded using the conversation ID.
  11. Llama 3.2 generates the answer.
  12. The response returns the answer and retrieved sources.

12.15 No-Match Behavior

If no relevant article is found, the AI must not pretend that a verified company solution exists. It may provide clearly labelled general troubleshooting advice.

{
  "conversationId": null,
  "message": "How do I configure an Oracle database replication cluster?"
}

Expected behavior:

  • The response states that no matching verified solution was found.
  • The response does not invent an internal company solution.
  • The sources list is empty when no article is retrieved.

12.16 Source Ticket Validation

A knowledge article may reference a source ticket. If provided, the source ticket must exist, be RESOLVED or CLOSED, and contain resolution notes.

For initial RAG testing, use:

"sourceTicketId": null

This permits creation of a manually verified knowledge article.

12.17 PostgreSQL Verification

Verify knowledge articles

SELECT id, title, source_ticket_id, verified, active, verified_by, created_at
FROM knowledge_articles
ORDER BY created_at DESC;

Verify vector metadata

SELECT
    id,
    metadata->>'articleId' AS article_id,
    metadata->>'title' AS title,
    metadata->>'verified' AS verified,
    metadata->>'active' AS active
FROM smartresolve_knowledge_vectors;

Verify RAG conversation messages

SELECT conversation_id, type, content, "timestamp"
FROM spring_ai_chat_memory
WHERE conversation_id = 'RAG_CONVERSATION_ID'
ORDER BY "timestamp" ASC;

12.18 Part 9 Testing Checklist

  • Confirm that Ollama is running.
  • Confirm that llama3.2 is installed.
  • Confirm that mxbai-embed-large is installed.
  • Create a knowledge article.
  • Verify the article in knowledge_articles.
  • Verify its vector metadata in smartresolve_knowledge_vectors.
  • Ask a semantically similar question using /api/ai/rag/chat.
  • Confirm that the response contains the article in sources.
  • Continue the conversation using the same conversation ID.
  • Test an unrelated question and confirm that no unsuitable article is returned.
