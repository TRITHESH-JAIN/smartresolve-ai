PART 9 - RAG WITH POSTGRESQL AND PGVECTOR

9.1 Implementation Objective

Part 9 was implemented to allow SmartResolve to answer employee questions using verified internal IT knowledge. Instead of sending only the employee's question to the LLM, the application first searches the knowledge base and adds relevant verified solutions to the prompt.

9.2 Models Used

The implementation uses two Ollama models with separate responsibilities:

ModelPurpose
llama3.2 Generates the final chat and RAG response.
mxbai-embed-large Converts article content and questions into embedding vectors. 
ollama pull llama3.2
ollama pull mxbai-embed-large

9.3 Knowledge Article Storage

Verified knowledge is stored in the knowledge_articles table. An administrator or active support engineer creates an article through the knowledge article controller. 

POST http://localhost:8080/api/knowledge/articles
{
  "title": "Frequent Wi-Fi disconnections on Windows laptop",
  "content": "Update the Wi-Fi adapter driver, restart WLAN AutoConfig, forget the wireless network, and connect again.",
  "sourceTicketId": null
}

The service validates the user, saves the article with verified = true and active = true, and then indexes it in the vector store.

9.4 Vector Storage

The application uses Spring AI's PostgreSQL vector store. Embeddings are stored in: 

smartresolve_knowledge_vectors

The vector metadata contains the article ID, title, verification status, active status, and optional source ticket ID.

The vector store is configured as follows:

spring.ai.vectorstore.pgvector.initialize-schema=true
spring.ai.vectorstore.pgvector.dimensions=1024
spring.ai.vectorstore.pgvector.distance-type=COSINE_DISTANCE
spring.ai.vectorstore.pgvector.index-type=HNSW
spring.ai.vectorstore.pgvector.table-name=smartresolve_knowledge_vectors

9.5 RAG Chat Endpoint

Employees use the RAG endpoint to ask questions:

POST http://localhost:8080/api/ai/rag/chat
{
  "conversationId": null,
  "message": "My Windows laptop disconnects from Wi-Fi frequently. What should I do?"
}

When the conversation ID is null, the service creates a new conversation. Follow-up requests must use the returned conversation ID.

9.6 RAG Service Flow

  1. RAGController receives the authenticated employee request.
  2. RAGService validates the employee and conversation ownership.
  3. The question is searched in the PostgreSQL vector store.
  4. Only documents matching verified == true and active == true are retrieved.
  5. Up to five relevant documents are selected with a similarity threshold of 0.60.
  6. The retrieved article content is formatted as knowledge context.
  7. The context is appended to the system prompt.
  8. Spring AI sends the prompt, context, and current question to Llama 3.2.
  9. The response and retrieved source articles are returned to the employee.

9.7 Prompt Construction

The retrieved article is not returned directly as the final answer. It is added to the prompt so that Llama 3.2 can explain it to the employee. 

System instructions
+ Verified knowledge retrieved from pgvector
+ Previous conversation messages
+ Current employee question
        |
        v
     Llama 3.2
        |
        v
   Final RAG response

9.8 Conversation Memory

RAG chat uses the same JDBC conversation memory mechanism as the normal AI chat feature.

TableStored data
chat_conversations Conversation owner, title, creation time, and update time.
SPRING_AI_CHAT_MEMORY User, assistant, system, and tool messages.

The same conversation ID must be sent for follow-up questions. A new conversation is created when conversationId is null.

9.9 RAG Response

{
  "conversationId": "RAG_CONVERSATION_ID",
  "answer": "You should update the Wi-Fi adapter driver and restart the WLAN AutoConfig service.",
  "sources": [
    {
      "articleId": "KNOWLEDGE_ARTICLE_ID",
      "title": "Frequent Wi-Fi disconnections on Windows laptop",
      "sourceTicketId": null
    }
  ],
  "timestamp": "2026-11-15T17:15:00"
}

The sources field shows which verified knowledge articles were used to produce the answer.

9.10 No Matching Knowledge

If no relevant verified article is found, the service tells the LLM not to pretend that an internal verified solution exists. The AI may provide clearly labelled general troubleshooting advice.

9.11 Database Verification

SELECT id, title, verified, active, verified_by, created_at
FROM knowledge_articles
ORDER BY created_at DESC;
SELECT
    id,
    metadata->>'articleId' AS article_id,
    metadata->>'title' AS title,
    metadata->>'verified' AS verified,
    metadata->>'active' AS active
FROM smartresolve_knowledge_vectors;
SELECT conversation_id, type, content, "timestamp"
FROM spring_ai_chat_memory
WHERE conversation_id = 'RAG_CONVERSATION_ID'
ORDER BY "timestamp" ASC;

9.12 Implemented Components

ComponentResponsibility
KnowledgeArticleControllerCreates and lists verified articles.
KnowledgeArticleServiceValidates articles, saves them, and indexes vectors.
RAGControllerExposes the RAG chat endpoint.
RAGServiceRetrieves documents, builds context, and calls the LLM.
KnowledgeArticleRepresents a verified knowledge article.
VectorStoreStores and searches pgvector embeddings.
ChatMemoryMaintains conversation history.

9.13 Part 9 Result

Part 9 is implemented. SmartResolve can store verified knowledge articles, create embeddings with mxbai-embed-large, retrieve relevant articles with PostgreSQL pgvector, add the retrieved knowledge to the Llama 3.2 prompt, and return an answer with its knowledge sources.
